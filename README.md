# ตาทิพย์ Navigator (Taa-Thip Navigator)

PWA ต้นแบบช่วยนำทางด้วยเสียงสำหรับผู้พิการทางสายตา ต่อยอดจากตาทิพย์เครื่องอ่านฉลากยา

> **ยังไม่ใช่ระบบนำทางที่ผ่านการรับรองความปลอดภัย** ใช้กับไม้เท้าหรือสุนัขนำทาง และทดสอบกับผู้ช่วยในพื้นที่ปลอดภัยก่อน แอปตรวจสิ่งกีดขวางได้เฉพาะที่มีคนบันทึกไว้ในแผนที่ (บันได ประตูกั้น เขตก่อสร้าง) ไม่รู้สภาพทางเท้าจริง สิ่งของที่วางขวางเฉพาะหน้า รถ หรือไฟคนข้าม และไม่สามารถรับรองว่าข้ามถนนได้ แอปนี้ทำสองอย่างคือ **ค้นหาสถานที่และนำทางด้วยเสียง** ไม่มีระบบขอความช่วยเหลือฉุกเฉินหรือแชร์ตำแหน่ง การทดสอบอัตโนมัติไม่แทน VoiceOver/TalkBack และการเดินจริง

## เริ่มต้น

ใช้ Node.js 22.12+ ที่เข้ากันได้กับ Vite และ npm (การตรวจรอบนี้ใช้ Node 26)

```sh
npm ci
npm run dev
```

เปิด localhost ตามที่แสดงในหน้าต่าง dev server การทดสอบ GPS บนมือถือใช้ HTTPS; HTTP ผ่าน IP ใน LAN ไม่ใช่ secure context

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

- ชุดเบราว์เซอร์เปิด production preview ที่ 127.0.0.1:4173 ต้องว่างก่อนรัน
- ใช้ GPS, speech engine และ API จำลอง ไม่ส่งข้อความฉุกเฉินหรือพิกัดจริง
- dev ปิด service worker; ตรวจ PWA/offline ด้วย build + preview
- รายละเอียดผลตรวจและรายการตรวจอุปกรณ์จริง: [Safety audit](docs/SAFETY-AUDIT.md)

## เสียง

แอป **พูดด้วยเสียงของตัวเอง** ผ่าน SpeechSynthesis และ **ถอยไปให้โปรแกรมอ่านหน้าจออ่านแทนเองอัตโนมัติ** เมื่อพูดเองไม่ได้ ไม่มีตัวเลือกให้ตั้งค่าและไม่มีปุ่มทดสอบเสียง

**ทำไมไม่พูดทั้งสองทางพร้อมกัน:** ถ้าแอปพูดไปด้วยและใส่ข้อความลง live region ไปด้วย VoiceOver จะอ่านประโยคเดียวกันซ้อนขึ้นมาอีกเสียงจนจับใจความไม่ได้ แอปจึงใส่ข้อความลง live region **เฉพาะตอนที่พูดเองไม่ได้เท่านั้น** ระหว่างที่พูดเองได้ live region จะว่าง โปรแกรมอ่านหน้าจอจึงไม่มีอะไรให้อ่านซ้ำ

ถอยไปใช้โปรแกรมอ่านหน้าจอเมื่อ:

- เบราว์เซอร์ไม่มี SpeechSynthesis
- เครื่องไม่มีเสียงของภาษาที่เลือก (อ่านไทยด้วยเสียงอังกฤษฟังไม่รู้เรื่อง ให้ VoiceOver ที่มีเสียงไทยอ่านดีกว่า)
- เครื่องยนต์เสียงไม่เริ่มพูดภายใน 3 วินาที หรือค้างกลางประโยค (เกิดจริงบน iOS ที่ยังไม่ปลดล็อกเสียง)

เสียงถูกปลดล็อกตอนกดปุ่มเริ่มใช้งาน ซึ่งต้องเป็นการแตะของผู้ใช้จริง ไม่งั้น iOS จะไม่ยอมให้ออกเสียงตลอดทั้ง session

### จุดที่เคยเงียบแล้วเพิ่มเสียงเข้าไป

- **หลังได้ตำแหน่งแล้ว** บอกว่าให้พิมพ์ชื่อสถานที่แล้วกดค้นหา เดิมเงียบสนิททั้งที่ผู้ใช้ยังไม่รู้ว่าต้องทำอะไรต่อ
- **ตอนเลือกจุดหมาย** ยืนยันชื่อที่เลือกก่อนเริ่มคำนวณเส้นทาง
- **ระหว่างทางตรงยาว** ย้ำคำแนะนำเดิมถ้าเงียบเกิน 45 วินาที เดิมคำเตือนผูกกับระยะถึงจุดเลี้ยวอย่างเดียว ทางตรง 350 เมตรจึงเงียบเกือบห้านาที นานพอที่ผู้ใช้จะเริ่มไม่แน่ใจว่าแอปยังทำงานอยู่ไหม

ข้อจำกัดที่เปลี่ยนไม่ได้: **ไม่มีทางรู้ว่าผู้ใช้ได้ยินจริงหรือไม่** เครื่องอาจปิดเสียงอยู่ ห้ามถือว่าประกาศแล้วเท่ากับผู้ใช้รับรู้แล้ว

**เปิดแอปไว้ด้านหน้า** ไม่พึ่งการทำงานเมื่อปิดหน้าจอหรือสลับแอป ระบบมือถืออาจพัก GPS/ตัวจับเวลา

## ภาษา

เปิดครั้งแรกเป็น **ภาษาอังกฤษเสมอ** แล้วกดปุ่มมุมขวาบนเปลี่ยนเป็นไทยได้ ระบบจำไว้ตลอดหลังจากนั้น

ตั้งใจไม่ดูภาษาของเบราว์เซอร์ เพราะจะทำให้เครื่องที่ตั้งเป็นไทยเปิดมาเป็นไทยทันที จนไม่มีจุดเริ่มต้นที่แน่นอนเวลาทดสอบหรืออธิบายให้คนอื่นฟัง

## หน้าจอ

แอปมีสิ่งที่กดได้ไม่กี่อย่าง และทุกอย่างใหญ่

- แผ่นกดหมวดหมู่สูง 92px ปุ่มระดับหน้าเต็มความกว้างสูง 64px รายการผลลัพธ์สูง 80px — ทั้งหมดใหญ่กว่าเกณฑ์ขั้นต่ำของ WCAG (48px) มาก เพราะผู้ใช้แตะโดยไม่เห็นตำแหน่งปุ่ม การกดพลาดไม่ใช่แค่ความรำคาญแต่หมายถึงเดินผิดทาง
- หน้าแรกมีสิ่งที่ต้องทำอยู่อย่างเดียวคือพิมพ์ชื่อที่จะไป แล้วกดค้นหา
- **ระหว่างนำทาง หน้าจอแสดงเฉพาะคำแนะนำถัดไปกับปุ่มพูดซ้ำและหยุดนำทาง** ช่องค้นหาหายไปทั้งหมด
- **ไม่มีหน้าตั้งค่า** ธีมตามการตั้งค่าของเครื่อง และขนาดตัวอักษรฐานตั้งไว้ใหญ่กว่าเว็บทั่วไปโดยทุกขนาดใช้หน่วย rem การตั้งขนาดตัวอักษรของเบราว์เซอร์จึงขยายทั้งแอปได้เอง

> **สิ่งที่แลกไป:** การตัดหน้าตั้งค่าออกแปลว่าผู้ใช้เปลี่ยนธีมหรือขนาดตัวอักษร**ในแอป**ไม่ได้ ต้องตั้งที่ระดับเครื่องหรือเบราว์เซอร์แทน ซึ่งมีผลกับทุกแอปที่เขาใช้

## การนำทางและความปลอดภัย

- ขอ GPS หลังผู้ใช้กดอนุญาตเท่านั้น มี deadline สำหรับตำแหน่งแรกและตำแหน่งค้าง 15 วินาที พร้อมยกเลิก callback เก่าหลังหยุด/ลองใหม่
- พักคำสั่งเดินเมื่อ GPS เก่าหรือผิดพลาด, accuracy เกิน 30 เมตร, เสียงล้มเหลว, แอปอยู่เบื้องหลัง หรือเปิดกล่องฉุกเฉิน
- ความแม่นยำเป็นเพียงค่าประเมิน ไม่ใช่หลักฐานว่าอยู่ฝั่งถนนหรือทางเท้าที่ถูกต้อง
- คำเตือนเลี้ยวใช้ระยะตามเส้นทาง ไม่ลัดผ่านอาคาร และไม่พูดว่าให้เลี้ยวทันทีโดยถือ GPS เป็นข้อยืนยัน
- เลื่อนไปขั้นตอนถัดไปต่อเมื่อ **มีหลักฐานว่าอยู่บนทางออกแล้ว** ไม่ใช่แค่ GPS เข้าใกล้จุดเลี้ยว มีสองเงื่อนไข: เพิ่งเลี้ยวผ่านมา (ระยะ 8-35 เมตรและเริ่มเห็นว่าอยู่บนทางออก) หรือเลี้ยวผ่านมานานแล้ว (อยู่บนทางออกชัดเจนและห่างจากทางเข้าเกิน 30 เมตร)
  เงื่อนไขที่สองจำเป็นเพราะทดสอบแล้วพบว่า **ถ้า GPS อัปเดตห่างกัน 40 เมตร ระบบจะค้างอยู่ขั้นตอนเดิมถาวร** พูดว่า "เลี้ยวขวา" ทั้งที่ผู้ใช้เลี้ยวไปแล้วและกำลังเดินอยู่บนถนนถัดไป และปุ่มยืนยันเลี้ยวก็หายไปแล้วเพราะแสดงเฉพาะตอนอยู่ใกล้จุดเลี้ยว
- ประกาศถึงจุดหมายได้ต่อเมื่อระบบติดตามอยู่บนช่วงสุดท้ายมาก่อนแล้ว ไม่ใช่กระโดดมาถึงในอัปเดตเดียว เพราะพิกัดที่ตรงกับปลายทางไม่ได้แปลว่าเดินมาถึงจริง อาจอยู่คนละฝั่งกำแพงหรือคนละชั้นของอาคาร
- เลี้ยวที่ GPS แยกไม่ออกมีปุ่มยืนยันว่าเลี้ยวผ่านแล้ว ต้องใช้หลังผู้ใช้ตรวจสถานการณ์จริง
- ออกนอกเส้นทางเกิน 40 เมตรสองตำแหน่งที่ต่างเวลากัน จะระงับคำแนะนำเก่า คำนวณใหม่ห่างกันอย่างน้อย 30 วินาที เมื่อคำนวณล้มเหลวจะแสดงข้อผิดพลาดและมีปุ่มลองใหม่
- ประกาศจบเมื่อเข้าปลายเส้นทางในช่วงสุดท้ายด้วย accuracy ไม่เกิน 15 เมตร ไม่ใช้ระยะถึงกึ่งกลางอาคารเพียงอย่างเดียว หากปลายทาง snap ห่างอาคารจะบอกระยะที่ยังเหลือ **ไม่ยืนยันว่าพบทางเข้า**
- คำเตือนจุดเสี่ยงอนุมานจากข้อมูลแยกและชื่อถนน จึงมีทั้งโอกาสเตือนผิดและพลาด ไม่ใช่ตัวตรวจทางข้าม รถ หรือสัญญาณไฟ
- รองรับการสั่นเฉพาะอุปกรณ์ที่มี Vibration API ไม่ใช้แทนเสียงหรือการรับรู้สิ่งแวดล้อม
- ยังไม่ได้เพิ่มการรับคำสั่งด้วย SpeechRecognition

## จบการเดินทาง

เมื่อถึงจุดหมาย แผงนำทางเหลือปุ่มเดียวคือ **"จบการเดินทาง"** เป็นปุ่มหลักสีปกติ ไม่ใช่ปุ่มสีแดงที่สื่อว่ากำลังยกเลิกอะไร เพราะการเดินทางสำเร็จแล้ว ส่วนปุ่มพูดคำแนะนำซ้ำถูกเอาออกเพราะไม่มีความหมายอีกต่อไป

กดแล้วประกาศว่าจบการเดินทางและย้ายโฟกัสกลับไปที่ช่องค้นหา พร้อมหาจุดหมายใหม่ทันที

## ค้นหาสถานที่

พิมพ์ชื่อแล้วกดปุ่มค้นหา ไม่มี autocomplete เพราะนโยบายของ Nominatim ห้ามไว้

เมื่อผลลัพธ์ว่าง แอปจะลองรูปแบบอื่นของคำค้นให้เองทีละแบบ แล้วหยุดทันทีที่เจอ:

| ความผิดพลาดที่คนพิมพ์จริง | ตัวอย่าง | ทำอะไร |
| --- | --- | --- |
| ตัวย่อ | "รพ.ศิริราช" · "รร.สวนกุหลาบ" · "มธ.ท่าพระจันทร์" · "สภ.เมือง" | ขยายเป็นคำเต็ม |
| คำนำหน้าที่ไม่มีในชื่อจริง | "สถานีรถไฟฟ้าวัดพระศรีมหาธาตุ" | ตัดคำนำหน้าออก |
| ไม่เว้นวรรคหน้าตัวเลข | "หมอชิต2" | เติมวรรค |
| มีจุดหรือวรรคเกิน | "ร.พ.ศิริราช" | ตัดจุดและวรรคออก |
| สะกดผิดตอนท้าย | "สยามพารากอนน" · "เอ็มควอเทีย" | ตัดท้ายทีละส่วนแล้วหาชื่อใกล้เคียง |

รองรับตัวย่อทั้งแบบมีจุดและไม่มีจุด มีวรรคและไม่มีวรรค เพราะคนพิมพ์ไม่เหมือนกัน และตัวย่อที่มีความหมายได้หลายแบบจะลองทุกแบบ ไม่เดาแทนผู้ใช้ — "รร." ลองทั้งโรงเรียนและโรงแรม

> ### ผลที่เป็นแค่ "ชื่อใกล้เคียง" ต้องบอกให้ชัด
>
> เมื่อทุกวิธีข้างบนยังไม่เจอ ระบบจะตัดท้ายคำค้นแล้วหาชื่อที่ใกล้เคียงมาแสดงแทนหน้าจอว่างเปล่า แต่ผลเหล่านี้ถูก **ติดธงและประกาศด้วยเสียงว่าไม่ใช่สิ่งที่พิมพ์หา** เพราะคนที่มองไม่เห็นเลือกจากเสียงอย่างเดียว ถ้าพิมพ์ "สยามพารากอน" แล้วได้ "สยามราม่า" โดยไม่รู้ว่าเป็นแค่ชื่อคล้าย อาจกดเลือกแล้วเดินไปผิดที่โดยไม่รู้ตัว

**ผลรวมหลังเพิ่มทั้งหมด: เจอ 10 จาก 10 คำที่ใช้ตัวย่อและสะกดผิด**

ยิงคำขอเพิ่มเฉพาะตอนผลว่างจริงเท่านั้น จึงไม่เพิ่มภาระในกรณีปกติ

### ตัวสำรองเมื่อ Nominatim ไม่เจอ

Nominatim จับคำแบบตรงตัว พิมพ์ไม่ครบคำหรือไม่เว้นวรรคแล้วไม่เจอเลย จึงเพิ่ม [Photon](https://photon.komoot.io) เป็นตัวสำรอง — เป็น geocoder ฟรีของ komoot ที่สร้างบน **ข้อมูล OSM ชุดเดียวกัน** แต่ทำ index แบบ full-text จึงจับคำบางส่วนได้

ทั้งสองตัว **เก่งคนละแบบอย่างชัดเจน** วัดจริงด้วยคำที่คนพิมพ์:

| คำค้น | Nominatim | Photon |
| --- | --- | --- |
| "สยามพารากอน" | ✅ | ❌ |
| "เซ็นทรัลเวิล" (พิมพ์ไม่ครบ) | ❌ | ✅ |
| "หมอชิต2" (ไม่เว้นวรรค) | ❌ | ✅ |
| "เทอมินอล21" | ❌ | ✅ |

เรียก Nominatim ก่อนเสมอเพราะจัดอันดับตรงกว่าและให้ที่อยู่เต็ม ส่วน Photon ถูกเรียก **เฉพาะตอนที่ผลว่างจริง** จึงไม่เพิ่มภาระในกรณีปกติ และถ้า Photon ล่ม ผู้ใช้เห็นว่า "ไม่พบ" ไม่ใช่ "บริการขัดข้อง"

**ผลรวมหลังเพิ่มตัวสำรอง: เจอ 14 จาก 14 คำทดสอบ** จากเดิม 8 จาก 11

### การจัดอันดับผลของ Photon

Photon คืนทางเท้าและอาคารที่ชื่อพ้องกันมาปนด้วย ค้น "เซ็นทรัลเวิล" แล้วเคยได้ "ดิ ออฟฟิศเศส แอท เซ็นทรัลเวิลด์" ขึ้นก่อน ทั้งที่มี "เซ็นทรัลเวิลด์" อยู่ในผล จึงจัดอันดับใหม่สามชั้น:

1. **ชื่อตรงกับที่พิมพ์แค่ไหน** — ขึ้นต้นตรงกันชนะการมีคำนั้นอยู่กลางชื่อ
2. **เป็นสถานที่ที่คนตั้งใจไป** ไม่ใช่ทางเท้าหรือถนนที่ชื่อพ้องกัน
3. **ชื่อสั้นกว่าชนะ** เพราะมักเป็นชื่อหลัก ส่วนชื่อยาวมักเป็นสิ่งที่อยู่ภายในสถานที่นั้น

> ### ⚠️ ที่ยังทำไม่ได้
>
> การจัดอันดับยังผิดได้เมื่อ Nominatim เจอผลลัพธ์ที่ "ผิดตัว" เช่น "รพ.รามา" ได้ "สะพานพระราม 8" — เพราะเจอผลแล้วจึงไม่เข้าเงื่อนไขถอยไปใช้ตัวสำรอง ทั้งสองบริการไม่มีการให้คะแนนความใกล้เคียงที่เอามาเทียบกันได้ ถ้าต้องการความทนทานระดับที่ผู้ใช้ทั่วไปคาดหวัง ต้องใช้ Places Autocomplete — ดูหัวข้อ **ถ้าจะเปลี่ยนไปใช้ Google**

## ค้นหารอบตัวตามหมวด

8 หมวด: รถเมล์/รถไฟฟ้า · ร้านสะดวกซื้อ · ห้องน้ำ · ร้านอาหาร · ร้านขายยา · โรงพยาบาล · ธนาคาร/เอทีเอ็ม · ราชการ/ตำรวจ

สำหรับผู้ใช้ที่มองป้ายร้านไม่เห็น จึงไม่รู้ว่ารอบตัวมีอะไรให้เอาชื่อไปพิมพ์ค้นหา ปุ่มหมวดหมู่เปลี่ยนคำถามเป็น "รอบตัวฉันมีอะไรบ้าง"

- **ดึงทุกหมวดในคำขอเดียว** แล้วกรองในเครื่อง กดหมวดแรกใช้เวลาประมาณ 2 วินาที หมวดถัดไปตอบทันทีจาก cache
  เดิมยิงแยกทีละหมวดตามที่กด ซึ่งพังเพราะ Overpass ตอบ 429 ตั้งแต่หมวดที่สาม
- **ขยายรัศมีเองอัตโนมัติ 800 เมตร ไป 2.5 และ 6 กิโลเมตร** ถ้ายังไม่เจอ
  ขั้นสุดท้ายไกลเกินกว่าจะเดินไหว แต่ยังมีประโยชน์เพราะบอกได้ว่าสิ่งที่ใกล้ที่สุดอยู่ไกลแค่ไหน ช่วยให้ตัดสินใจเรียกรถแทนได้ ดีกว่าบอกว่าไม่พบเฉยๆ
- สถานที่ที่ไม่มีชื่อใน OSM (ตู้เอทีเอ็ม ห้องน้ำ ป้ายรถเมล์) ใช้ชื่อหมวดแทน ไม่ปล่อยว่างจนกลายเป็นปุ่มที่ screen reader อ่านไม่ได้
- ผลลัพธ์ปักหมุดบนแผนที่ มีเลขกำกับตรงกับลำดับในรายการ

> ### ⚠️ ข้อมูล OSM ในไทยนอกใจกลางเมืองบางมาก
>
> วัดจริงในรัศมี 800 เมตร: ย่านสยามเจอร้านสะดวกซื้อ 30 แห่ง ร้านขายยา 5 แห่ง ห้องน้ำ 19 แห่ง แต่แถววัดพระศรีมหาธาตุและบางนาเจอร้านสะดวกซื้อ 5-6 แห่ง และ **ร้านขายยา โรงพยาบาล ห้องน้ำ เจอศูนย์แห่ง**
>
> ไม่ใช่ข้อผิดพลาดของโค้ดหรือของ API แต่เป็นเพราะ OSM เป็นข้อมูลอาสาสมัคร การขยายรัศมีอัตโนมัติช่วยได้บางส่วนแต่แก้ที่ต้นเหตุไม่ได้

## ตรวจสิ่งกีดขวางบนเส้นทาง

สแกนหนึ่งครั้งเมื่อได้เส้นทางใหม่ แล้วรายงานภาพรวมทั้งเส้นทางก่อนก้าวแรก เพราะการรู้ล่วงหน้าว่ามีบันไดกี่จุดทำให้ตัดสินใจได้ว่าจะไปเส้นทางนี้ไหมหรือจะขอให้คนช่วย

| ตรวจได้จากข้อมูลแผนที่ | รายละเอียดที่ได้ด้วยถ้ามีคนแมปไว้ |
| --- | --- |
| บันได | จำนวนขั้น · ขึ้นหรือลง · มีราวจับหรือไม่ |
| ประตู เสากั้น แผงกั้น | – |
| ขอบทางสูง | – |
| เขตก่อสร้าง | – |
| ทางข้ามที่ไม่มีเบรลล์บล็อก | – |
| ทางแคบกว่า 90 ซม. | ความกว้างที่ระบุไว้ |

เตือนด้วยเสียงล่วงหน้า 30 เมตรเฉพาะชนิดที่ทำให้บาดเจ็บได้ทันที (บันได เขตก่อสร้าง) ที่เหลืออยู่ในรายงานก่อนออกเดินทางเท่านั้น เพราะถ้าเตือนทุกอย่างระหว่างเดิน เสียงจะถี่จนกลบคำสั่งนำทาง

> **ตรวจไม่ได้เลย:** มอเตอร์ไซค์จอดบนทางเท้า แผงลอย ถังขยะ ป้ายตั้งพื้น สายไฟห้อย ต้นไม้ล้ม ซึ่งในไทยคือสิ่งกีดขวางที่พบบ่อยที่สุด การตรวจสิ่งเหล่านี้ต้องใช้กล้องและการประมวลผลภาพ ซึ่งอยู่นอกขอบเขตของเว็บแอป **ต้องใช้ไม้เท้าตรวจทางตามปกติเสมอ** ข้อความนี้แสดงอยู่ในแอปตลอดเวลา ไม่ซ่อนในหน้าตั้งค่า

**"ตรวจไม่สำเร็จ" ไม่เท่ากับ "ไม่มีสิ่งกีดขวาง"** แยกสองสถานะนี้ขาดจากกันทุกชั้น ถ้าสแกนล้มเหลวแล้วไปบอกว่าเส้นทางไม่มีสิ่งกีดขวาง เท่ากับหลอกให้เดินอย่างมั่นใจบนเส้นทางที่ยังไม่เคยตรวจ มีเทสต์เบราว์เซอร์ล็อกพฤติกรรมนี้ไว้

ข้อมูลที่ได้เป็นภาพนิ่ง ณ เวลาที่สแกน ไม่อัปเดตระหว่างเดิน และเส้นทางที่คำนวณใหม่จะสแกนใหม่

## บริการภายนอกและข้อจำกัด

ไม่มี API key แต่บริการสาธารณะมีข้อจำกัดและไม่มีความพร้อมใช้งานที่รับประกัน **ไม่เหมาะกับการปล่อยใช้งานหนักหรือเป็นระบบความปลอดภัยหลัก**

### Nominatim

Nominatim จับคำแบบตรงตัว คำที่คนพูดติดปากแต่ไม่มีในชื่อที่บันทึกไว้ทำให้ไม่เจอเลย — ชื่อในแผนที่คือ "สถานีวัดพระศรีมหาธาตุ" แต่คนพิมพ์ "สถานีรถไฟฟ้าวัดพระศรีมหาธาตุ" แล้วได้ศูนย์รายการ เมื่อผลว่าง แอปจะตัดคำนำหน้าทั่วไป (สถานีรถไฟฟ้า ห้าง ร้าน BTS MRT) แล้วค้นอีกครั้งหนึ่งรอบ ยิงเพิ่มเฉพาะตอนผลว่างจริงเท่านั้น

[นโยบายทางการ](https://operations.osmfoundation.org/policies/nominatim/) ห้าม autocomplete และจำกัดรวมไม่เกิน 1 คำขอ/วินาที **ต่อแอป รวมผู้ใช้ทั้งหมด** ค้นหาเมื่อกดปุ่มเท่านั้น หน่วง 1 วินาที คิวค้นหา/reverse/retry ใช้ช่วงห่างขั้นต่ำ 1.1 วินาที และ cache ผลซ้ำในหน่วยความจำ 10 นาที

ตัวจำกัดฝั่ง client **ไม่ควบคุมยอดรวมจากหลายเครื่องหรือหลายแท็บ** จึงยังไม่พอสำหรับบริการสาธารณะที่มีผู้ใช้พร้อมกัน ก่อนขยายต้องใช้ backend ควบคุมยอดรวมและเปลี่ยน provider ได้โดยไม่อัปเดต client หรือใช้บริการที่รองรับโหลดตามข้อตกลง ห้าม bulk geocoding

### Photon

[บริการฟรีของ komoot](https://photon.komoot.io) ไม่ต้องใช้ key ใช้ข้อมูล OSM ชุดเดียวกับ Nominatim เรียกเฉพาะตอนที่ Nominatim ไม่เจออะไรเลย และต่อคิวเว้นระยะ 1 วินาทีเหมือนกัน

เป็นบริการที่เขาเปิดให้ใช้ด้วยความเอื้อเฟื้อ ไม่มี SLA เช่นเดียวกับตัวอื่นในโปรเจกต์นี้ ถ้าล่มจะกระทบเฉพาะคำค้นที่ Nominatim จับไม่ได้ ส่วนที่เหลือทำงานตามปกติ

### Routing

ใช้ OSRM ของ [FOSSGIS](https://routing.openstreetmap.de/) endpoint `routed-foot` เท่านั้น **ถ้าล่มไม่ถอยไปใช้เส้นทางรถยนต์** การใส่คำว่า walking ใน URL ไม่ได้ทำให้ server ที่เตรียมข้อมูลรถยนต์กลายเป็นบริการเดินเท้า

การร้องขอมี timeout, retry แบบ backoff และเคารพ Retry-After รวมถึง cooldown ต่อ provider; ข้อมูลผิดรูปถูกปฏิเสธ เว้นคำนวณใหม่อัตโนมัติ 30 วินาที บริการฟรีไม่รับรอง SLA/ความครบถ้วนของทางเท้า

### Overpass API

ใช้ตรวจสิ่งกีดขวางบนเส้นทางอย่างเดียว ไม่ต้องใช้ key แต่เป็นทรัพยากรบริจาคที่ **บล็อก IP ง่ายมาก** — ระหว่างพัฒนา ยิงทดสอบไปไม่กี่สิบครั้งก็โดนบล็อกชั่วคราวแล้ว

- ต่อคิวคำขอห่างกันอย่างน้อย 1.5 วินาที และ cache ผล 30 นาที เพราะบันไดกับเสากั้นไม่ได้ย้ายที่ทุกชั่วโมง
- วนลอง mirror ทีละตัวเมื่อล่ม แล้วจำตัวที่ใช้ได้ไว้ใช้ต่อ **ตั้งใจให้รายการสั้นแค่สองตัว** เพราะตอนแรกใส่ไว้สี่ตัวแล้วกลายเป็นโทษ: mirror ที่เข้าถึงไม่ได้ทำให้ต้องรอ timeout ทีละตัวจนรวมเป็นนาที ผู้ใช้เห็นแค่ว่า "ค้นหาไม่ได้" โดยไม่รู้ว่ากำลังรออะไร
- timeout 10 วินาที สั้นกว่าค่าในตัว query เพราะคนที่ยืนรอกลางทางควรได้คำตอบว่าไม่ได้ภายในเวลาที่ยังรอไหว
- **ไม่ใช้ค้นชื่อสถานที่** เพราะทดสอบแล้วการค้นชื่อแบบ regex ในรัศมีกว้างใช้เวลา 10-90 วินาทีและมักล้มเหลว
- ตอบช้ากว่า Nominatim มาก (1-5 วินาที) จึงบอกด้วยเสียงว่ากำลังค้นหาอยู่
- ใช้เฉพาะ mirror ที่ตรวจสอบที่มาได้ เพราะคำขอแต่ละครั้งมีพิกัดของผู้ใช้ติดไปด้วย
- ลดจุดของเส้นทางก่อนส่ง (เว้นระยะ และไม่เกิน 60 จุด) เพื่อไม่ให้ URL ยาวเกินและเซิร์ฟเวอร์ทำงานหนักเกินจำเป็น
- เมื่อทุก mirror ล่ม การค้นรอบตัวและการตรวจสิ่งกีดขวางจะรายงานว่าใช้ไม่ได้ ส่วนการค้นด้วยชื่อและการนำทางยังทำงานตามปกติ

### Map tiles / PWA

ใช้ canonical HTTPS URL พร้อม attribution ตาม [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) เปิดแผนที่ตามที่ผู้ใช้เลือกเท่านั้น ไม่ prefetch หรือมีปุ่มดาวน์โหลดพื้นที่

เก็บ app shell และสำเนา tiles ที่ดูไปแล้วสำหรับ revisits ใช้ HTTP cache ของ browser และ fallback cache จำกัด 500 tiles/7 วัน ไม่รับรองแผนที่ครบเมื่อ offline การค้นหา/reverse/เส้นทางใหม่ต้องใช้เน็ต ผลเส้นทางไม่เก็บถาวร การ reload จึงไม่กู้การนำทางเดิม

Service worker ไม่อัปเดตอัตโนมัติระหว่างนำทาง ปุ่มอัปเดตถูกปิดจนหยุดนำทาง

### ข้อควรระวังที่สำคัญที่สุด

> **ห้ามใส่ API key ของ Google ไว้ในโค้ดฝั่งเบราว์เซอร์** ใครก็เปิดดูได้จาก DevTools แล้วเอาไปใช้จนบิลขึ้นเป็นของเรา
> การจำกัด key ด้วย HTTP referrer ช่วยได้บ้างแต่ปลอมได้ **ต้องมี backend ทำหน้าที่ proxy** ซึ่งแปลว่าต้องมีเซิร์ฟเวอร์ที่ดูแลและจ่ายค่าใช้จ่ายต่อเนื่อง

นอกจากนี้ข้อกำหนดของ Google ห้ามเอาข้อมูล Places ไปแสดงบนแผนที่ที่ไม่ใช่ Google Maps ถ้าใช้ Places แล้วยังวาดบน Leaflet + OSM tiles อยู่ จะผิดข้อกำหนด ต้องเปลี่ยนไปใช้ Google Maps JavaScript API ด้วย ซึ่งคิดเงินแยกอีกส่วน

### วิธีสมัคร API key ทีละขั้น

> ต้องใช้บัญชี Google และ **บัตรเครดิต/เดบิตที่ใช้กับต่างประเทศได้** Google บังคับให้ผูกบัตรก่อน แม้จะใช้อยู่ในโควตาฟรีก็ตาม

**1. สร้างโปรเจกต์**

เข้า [console.cloud.google.com](https://console.cloud.google.com) → กดชื่อโปรเจกต์บนแถบบน → **New project** → ตั้งชื่อ เช่น `tatip-navigator` → **Create**

**2. เปิด billing**

เมนูซ้าย → **Billing** → **Link a billing account** → **Create billing account** → กรอกที่อยู่และข้อมูลบัตร

Google จะตัดเงินทดสอบจำนวนเล็กน้อยเพื่อยืนยันบัตร แล้วคืนให้

**3. ตั้งงบประมาณและการแจ้งเตือน — ทำก่อนสร้าง key**

**Billing** → **Budgets & alerts** → **Create budget** → ตั้งวงเงินที่รับได้ เช่น 200 บาท → ตั้งแจ้งเตือนที่ 50%, 90%, 100%

> ⚠️ **ขั้นนี้ห้ามข้าม** งบประมาณของ Google **แจ้งเตือนอย่างเดียว ไม่ตัดบริการให้อัตโนมัติ** ถ้าคีย์รั่วแล้วมีคนเอาไปใช้ บิลจะวิ่งต่อจนกว่าจะมีคนเข้าไปปิด การแจ้งเตือนคือสิ่งเดียวที่ทำให้รู้ทัน

**4. เปิด API ที่จะใช้**

เมนูซ้าย → **APIs & Services** → **Library** → ค้นหาและกด **Enable** ทีละตัว:

| API | ใช้ทำอะไรในแอปนี้ |
| --- | --- |
| **Places API (New)** | ค้นหาสถานที่ด้วยชื่อ — ตัวที่แก้ปัญหาพิมพ์ไม่ครบ/สะกดผิด |
| **Geocoding API** | ปุ่ม "ฉันอยู่ที่ไหน" (แปลงพิกัดเป็นที่อยู่) |
| **Routes API** | เส้นทางเดินเท้า (ถ้าจะเลิกใช้ OSRM ด้วย) |

เปิดเท่าที่จะใช้จริง ยิ่งเปิดน้อยยิ่งจำกัดความเสียหายได้มากถ้าคีย์รั่ว

**5. สร้าง key**

**APIs & Services** → **Credentials** → **Create credentials** → **API key** → คัดลอกคีย์เก็บไว้

**6. จำกัดสิทธิ์ของ key ทันที**

กดชื่อคีย์ที่เพิ่งสร้าง → ในหัวข้อ **API restrictions** เลือก **Restrict key** แล้วติ๊กเฉพาะ API ที่เปิดไว้ในขั้นที่ 4

ส่วน **Application restrictions** ให้เลือก **None** เพราะคีย์จะอยู่ฝั่งเซิร์ฟเวอร์ ไม่ใช่ในเบราว์เซอร์ (Vercel ใช้ IP ไม่คงที่ จึงจำกัดด้วย IP ไม่ได้)

> การจำกัดด้วย HTTP referrer ใช้ได้เฉพาะคีย์ที่อยู่ในเบราว์เซอร์ ซึ่ง**เราไม่ทำ** เพราะปลอม referrer ได้ง่าย

**7. ใส่คีย์ลง Vercel**

โปรเจกต์บน Vercel → **Settings** → **Environment Variables** → เพิ่ม

| Name | Value | Environment |
| --- | --- | --- |
| `GOOGLE_MAPS_KEY` | คีย์ที่คัดลอกมา | Production, Preview, Development |

**ห้ามตั้งชื่อขึ้นต้นด้วย `VITE_`** เพราะ Vite จะฝังค่านั้นลงไปในไฟล์ JavaScript ที่ส่งให้เบราว์เซอร์ ซึ่งเท่ากับเปิดคีย์ให้ทุกคนเห็น

**8. ห้ามคอมมิตคีย์ลง git**

ถ้าทดสอบในเครื่อง ให้ใส่ไว้ใน `.env.local` ซึ่ง `.gitignore` ครอบคลุมอยู่แล้ว (`*.local`)

หากเผลอคอมมิตไปแล้ว ให้ถือว่าคีย์นั้นรั่วถาวร — ต้องเข้าไป **Delete** คีย์เดิมแล้วสร้างใหม่ การลบ commit ทีหลังไม่ช่วย เพราะคีย์ถูกอ่านไปแล้วได้

### ค่าใช้จ่ายโดยประมาณ

Google Maps Platform ให้โควตาเรียกฟรีต่อเดือนของแต่ละ SKU เกินจากนั้นคิดเป็นรายครั้ง โครงสร้างราคาเปลี่ยนเป็นระยะ ให้ดูตัวเลขล่าสุดที่ [หน้าราคาอย่างเป็นทางการ](https://mapsplatform.google.com/pricing/) เสมอ อย่าอิงตัวเลขในเอกสารนี้

วิธีลดค่าใช้จ่ายที่ได้ผลจริง:

- **cache ผลลัพธ์** — แอปนี้ cache การค้นหาซ้ำไว้ 10 นาทีอยู่แล้ว ย้ายมาใช้ Google ก็ยังได้ประโยชน์เดิม
- **ใช้ session token กับ Autocomplete** — Google คิดเงินการพิมพ์ทั้งชุดจนถึงการเลือกเป็นหนึ่งครั้ง ถ้าไม่ส่ง token จะถูกคิดทุกตัวอักษรที่พิมพ์
- **ขอเฉพาะฟิลด์ที่ใช้** ผ่าน `X-Goog-FieldMask` — ยิ่งขอฟิลด์มากยิ่งขึ้นชั้นราคาที่แพงขึ้น

### ทำอย่างไร

โครงสร้างของโปรเจกต์รองรับการเปลี่ยนไว้แล้ว ทุก service ถูกผูกที่ [`src/services/index.ts`](src/services/index.ts) จุดเดียว

**1. สร้าง backend เล็กๆ ทำหน้าที่ proxy** (เช่น Vercel Serverless Function) เก็บคีย์ไว้ฝั่งเซิร์ฟเวอร์

```ts
// api/places.ts — คีย์อยู่ใน environment variable ของ Vercel ไม่เคยออกไปถึงเบราว์เซอร์
export default async function handler(request: Request) {
  const { searchParams } = new URL(request.url)
  const response = await fetch('https://places.googleapis.com/v1/places:searchNearby', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Goog-Api-Key': process.env.GOOGLE_MAPS_KEY!,
      'X-Goog-FieldMask': 'places.displayName,places.location,places.formattedAddress',
    },
    body: JSON.stringify({
      includedTypes: [searchParams.get('type')],
      maxResultCount: 12,
      locationRestriction: {
        circle: {
          center: {
            latitude: Number(searchParams.get('lat')),
            longitude: Number(searchParams.get('lng')),
          },
          radius: Number(searchParams.get('radius')),
        },
      },
    }),
  })
  return new Response(await response.text(), {
    headers: { 'Content-Type': 'application/json' },
  })
}
```

**2. เขียน implementation ใหม่** ที่ implement interface เดิม แปลงข้อมูลของ Google เป็นไทป์กลางของแอป

```ts
// src/services/impl/googlePlacesService.ts
import type { NearbyOptions, PlacesService } from '@/services/interfaces'
import type { LatLng, Place, PlaceCategory } from '@/types'

/** หมวดของแอป -> ชนิดสถานที่ของ Google */
const GOOGLE_TYPES: Record<PlaceCategory, string> = {
  transit: 'transit_station',
  convenience: 'convenience_store',
  food: 'restaurant',
  pharmacy: 'pharmacy',
  hospital: 'hospital',
  bank: 'bank',
  toilets: 'public_bathroom',
  government: 'local_government_office',
}

export const googlePlacesService: PlacesService = {
  async findNearby(category, center: LatLng, options: NearbyOptions = {}): Promise<Place[]> {
    const params = new URLSearchParams({
      type: GOOGLE_TYPES[category],
      lat: String(center.lat),
      lng: String(center.lng),
      radius: String(options.radiusM ?? 800),
    })
    const response = await fetch(`/api/places?${params}`, { signal: options.signal })
    const data = await response.json()

    return (data.places ?? []).map((place: GooglePlace) => ({
      id: place.id,
      name: place.displayName?.text ?? '',
      address: place.formattedAddress ?? '',
      location: { lat: place.location.latitude, lng: place.location.longitude },
      categoryKey: category,
    }))
  },
}
```

**3. สลับที่ composition root บรรทัดเดียว**

```diff
- export const placesService: PlacesService = overpassPlacesService
+ export const placesService: PlacesService = googlePlacesService
```

ส่วนอื่นของแอปทั้งหมด — hook, component, การประกาศเสียง, การนำทาง — **ไม่ต้องแก้อะไรเลย** เพราะทำงานกับไทป์กลาง (`Place`, `Route`) ไม่ได้ผูกกับรูปร่างข้อมูลของผู้ให้บริการรายใด

ทำแบบเดียวกันได้กับ `GeocodingService` (ค้นด้วยชื่อ) และ `RoutingService` (เส้นทาง)

### คำแนะนำ

ถ้าเป็นงานเรียนหรือต้นแบบ **ใช้ของเดิมก่อน** เพราะไม่มีค่าใช้จ่ายและไม่ต้องดูแลเซิร์ฟเวอร์ ข้อมูลในย่านใจกลางเมืองเพียงพอสำหรับการสาธิต

ถ้าจะให้คนตาบอดใช้จริงทั่วกรุงเทพและต่างจังหวัด **ควรเปลี่ยนเป็น Google Places** เพราะการค้นหาร้านขายยาแล้วได้ศูนย์รายการทั้งที่มีร้านอยู่จริง คือความล้มเหลวที่ผู้ใช้รับไม่ได้ และต้องเตรียมงบสำหรับ backend กับค่า API ด้วย

## ความเป็นส่วนตัว

เอกสารนี้อธิบายการทำงานของโค้ด ไม่ใช่การรับรองว่าผ่าน PDPA หรือข้อกฎหมายทั้งหมด

| ข้อมูล | ที่เก็บ/ผู้รับ |
| --- | --- |
| GPS และเส้นทางระหว่างใช้ | หน่วยความจำในแอป ไม่สร้างประวัติเส้นทางถาวร |
| คำค้น/ตำแหน่งที่ reverse | ส่งให้ Nominatim และส่งให้ Photon ด้วยเมื่อ Nominatim ไม่เจอ; ผล cache ในหน่วยความจำ 10 นาที |
| ต้นทางและปลายทางที่ขอเส้นทาง | ส่งให้ FOSSGIS |
| ตำแหน่งที่ค้นรอบตัว และแนวเส้นทางที่สแกนสิ่งกีดขวาง | ส่งให้ Overpass mirror ที่ใช้อยู่; ผล cache ในหน่วยความจำ 30 นาที |
| Tiles ที่เปิดดู | ผู้ให้บริการทราบพื้นที่ที่ร้องขอ/IP; browser/cache อาจบอกพื้นที่ที่เคยดู |
| ภาษาที่เลือก | localStorage บนเครื่อง (เป็นข้อมูลเดียวที่แอปเก็บถาวร) |
| เสียง | แอปสังเคราะห์เสียงด้วย SpeechSynthesis ของเบราว์เซอร์ หรือให้โปรแกรมอ่านหน้าจอของระบบอ่าน ไม่มีเสียงถูกส่งออกจากเครื่อง |
| Hosting | โฮสต์อาจมี access logs/IP ตามนโยบายของโฮสต์ |

ห้ามใส่ข้อมูลลับในคำค้น เพราะคำค้นถูกส่งไปยังผู้ให้บริการภายนอก

แอปไม่เก็บประวัติตำแหน่งหรือเส้นทาง และไม่มีหน้าตั้งค่า สิ่งเดียวที่บันทึกไว้คือภาษาที่เลือก หากต้องการล้าง ให้ล้าง site data ของเว็บนี้จากการตั้งค่าเบราว์เซอร์

## โครงสร้างและการเปลี่ยนผู้ให้บริการ

React + Vite + TypeScript + Tailwind, Leaflet/react-leaflet, react-i18next และ vite-plugin-pwa

- `src/components/`: หน้าจอและปุ่ม
- `src/hooks/`: GPS, navigation, ค้นหาสถานที่, ตรวจสิ่งกีดขวาง, announcements
- `src/services/interfaces/`: สัญญากลางของ geocoding/routing/places/obstacle/map/speech
- `src/services/impl/`: adapter ภายนอก (รวม compositeGeocodingService ที่เรียง Nominatim ก่อน Photon)
- `src/services/index.ts`: composition root
- `src/i18n/locales/`: ไทย/อังกฤษ
- `tests/`: regression และ browser tests

Geocoding/routing เปลี่ยน adapter ที่ composition root ได้โดยไม่แก้ hook นำทาง ส่วน visual map ยังใช้ react-leaflet ใน MapView/SharedLocationView หากย้ายไป Google Maps SDK ต้องเปลี่ยน renderer เหล่านี้ด้วย ไม่ใช่เปลี่ยน URL tile เพียงอย่างเดียว

## Deploy บน Vercel

1. Import Git repository ที่ต้องการ
2. Framework: Vite; Build: `npm run build`; Output: `dist`; Install: `npm ci`
3. ไม่ต้องมี API key หรือ environment variables สำหรับค่าตั้งต้น
4. ใช้ HTTPS URL ทดสอบ permissions/เสียง/PWA บนมือถือ
5. ใช้ preview deployment ตรวจรายการอุปกรณ์จริงก่อน promote production

แอปใช้ hash สำหรับหน้ารับ snapshot จึงไม่ต้อง rewrite เส้นทางนั้น เมื่ออัปเดตให้หยุดนำทางและเลือกอัปเดตเวอร์ชัน การติดตั้ง PWA และความสามารถแต่ละ API ต่างกันตาม browser/OS

## ก่อนใช้เดินทางจริง

ต้องทดสอบ VoiceOver + Safari บน iPhone, TalkBack + Chrome บน Android ทั้งไทย/อังกฤษ รวม PWA ที่ติดตั้ง หูฟัง/ลำโพง การรับสาย ปิดจอ สลับแอป GPS ผิดฝั่งถนน และเน็ตหลุด โดยมีผู้ช่วยในพื้นที่ควบคุม ยังไม่ควรใช้นำทางลำพังจนกว่าจะผ่านการทดสอบเหล่านี้
