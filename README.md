# ตาทิพย์ Navigator (Taa-Thip Navigator)

แอปนำทางด้วยเสียงสำหรับผู้พิการทางสายตา — Progressive Web App ต่อยอดจากโปรเจกต์ **ตาทิพย์** (เครื่องอ่านฉลากยาด้วย AI)

> **สถานะ: เสร็จครบทั้ง 6 เฟส** — PWA ติดตั้งได้ ใช้งานออฟไลน์บางส่วนได้ ผ่านเกณฑ์ contrast ของ WCAG และพร้อม deploy

## Tech Stack

| ส่วน | เทคโนโลยี | ต้องใช้ API key |
| --- | --- | --- |
| Framework | React 19 + Vite + TypeScript | – |
| Styling | Tailwind CSS v4 | – |
| แผนที่ | Leaflet + react-leaflet + OpenStreetMap tiles | ไม่ต้อง |
| ค้นหาสถานที่ / reverse geocoding | Nominatim | ไม่ต้อง |
| คำนวณเส้นทางเดินเท้า | OSRM ของ FOSSGIS (`routed-foot`) | ไม่ต้อง |
| ตำแหน่ง | Geolocation API (`watchPosition`) | – |
| เสียง | Web Speech API (SpeechSynthesis / SpeechRecognition) | – |
| 2 ภาษา | react-i18next (th / en) | – |

### ทดสอบบนมือถือจริง

Geolocation API และ Web Speech API **ต้องรันบน HTTPS หรือ localhost เท่านั้น** เปิดผ่าน `http://192.168.x.x:5173`
เบราว์เซอร์จะไม่ยอมให้ขอตำแหน่ง ทางเลือก:

- deploy ขึ้น Vercel แล้วเปิดจากมือถือ (ง่ายที่สุด)
- หรือใช้ tunnel เช่น `ngrok http 5173`

### หลักการ service layer (สำคัญ)

ทุก component และ hook **ต้อง import จาก `@/services` เท่านั้น ห้าม import จาก `services/impl/` โดยตรง**
ถ้าวันหนึ่งอยากย้ายจาก OpenStreetMap ไป Google Maps:

1. เขียน implementation ใหม่ใน `services/impl/` ที่ implement interface เดิม
2. แก้บรรทัดผูก implementation ใน `services/index.ts` บรรทัดเดียว
3. ไม่ต้องแตะ component / hook ใดๆ

โดเมนไทป์กลาง (`LatLng`, `Route`, `RouteStep`, `ManeuverType`) ถูกออกแบบให้เป็นกลาง ไม่ใช่ shape ของ OSRM หรือ Leaflet
ดังนั้น implementation มีหน้าที่แปลงข้อมูลของผู้ให้บริการมาเป็นไทป์กลางเสมอ

## ⚠️ ข้อจำกัดของบริการฟรี (อ่านก่อนใช้งานจริง)

โปรเจกต์นี้ใช้บริการสาธารณะฟรีทั้งหมด **เหมาะกับงานเรียน / ต้นแบบ / เดโม เท่านั้น** ไม่เหมาะกับโปรดักชันจริงที่มีผู้ใช้จำนวนมาก

### Nominatim (ค้นหาสถานที่)

- นโยบายกำหนด **ไม่เกิน 1 คำขอต่อวินาที** ยิงถี่กว่านี้อาจโดนบล็อก IP
- ห้ามใช้ทำ bulk geocoding
- โปรเจกต์นี้ป้องกันด้วย: debounce การค้นหา 1 วินาที (`SEARCH_DEBOUNCE_MS`), ตัวคุมคิวคำขอขั้นต่ำ 1.1 วินาที (`NOMINATIM_MIN_INTERVAL_MS`), และ cache ผลลัพธ์ที่ค้นซ้ำ (Phase 4)

### OSRM (คำนวณเส้นทาง) — มีข้อควรระวังสำคัญ

> ⚠️ **`router.project-osrm.org` (demo server) ติดตั้งไว้เฉพาะ profile รถยนต์**
> ตรวจสอบแล้วด้วยพิกัดชุดเดียวกัน: เรียก `/driving/`, `/foot/`, `/walking/`, `/bike/` ได้ผลลัพธ์ **เท่ากันเป๊ะทุก profile** (1,621 ม. / 197 วิ = ~29 กม./ชม. ซึ่งเป็นความเร็วรถ)
> สำหรับแอปนำทางคนตาบอด นี่คือปัญหาด้านความปลอดภัย เพราะจะพาเดินตามถนนรถ ไม่ใช้ทางเท้า ไม่สนใจทางข้าม และบอกเวลาผิดหลายเท่า

โปรเจกต์นี้จึงใช้ **`routing.openstreetmap.de/routed-foot`** ของ FOSSGIS (อินสแตนซ์เดียวกับที่เว็บ openstreetmap.org ใช้) ซึ่งติดตั้ง profile เดินเท้าไว้จริง — เส้นทางเดียวกันได้ 742 ม. / 593 วิ (1.25 ม./วิ) และใช้ทางเดินในซอย

- ยังคงเป็นบริการฟรีแบบ fair use **ไม่มี SLA** ห้ามใช้งานหนัก
- ถ้า FOSSGIS ล่ม ระบบจะถอยไปใช้ demo server อัตโนมัติ แต่จะ **ติดธง `usedFallbackProfile`** และ **พูดเตือนผู้ใช้** ว่าเป็นเส้นทางรถ พร้อมคำนวณเวลาใหม่ด้วยความเร็วเดิน (1.25 ม./วิ) แทนเวลาขับรถ
- โปรเจกต์นี้ป้องกันเพิ่มด้วย: จำกัดการคำนวณเส้นทางใหม่ไม่ถี่กว่า 30 วินาที/ครั้ง + retry แบบ exponential backoff + แจ้งเตือนด้วยเสียงทันทีเมื่อบริการล่ม

### OpenStreetMap tile server

- มี [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) ห้าม bulk download tile และต้องแสดง attribution เสมอ

### ถ้าจะขยายเป็นโปรดักชันจริง

| ต้องการ | ทางเลือก |
| --- | --- |
| Geocoding | self-host Nominatim, หรือใช้ Photon / LocationIQ / Mapbox / Google Places (มีค่าใช้จ่าย) |
| Routing | self-host OSRM หรือ Valhalla, หรือ GraphHopper / Mapbox Directions |

## การจัดการ GPS (Phase 1)

`useGeolocation` ใช้ `watchPosition` และครอบเคสที่ผู้ใช้ตาบอดจะเดือดร้อนถ้าไม่จัดการ — **ทุกเคสมีเสียงพูดบอก ไม่ใช่แค่ข้อความบนจอ**

| สถานการณ์ | สิ่งที่เกิดขึ้น |
| --- | --- |
| ยังไม่กดเริ่ม | ไม่ขอสิทธิ์อัตโนมัติ — อธิบายเหตุผลก่อน แล้วให้ผู้ใช้แตะปุ่มเอง (โปร่งใส + ปลดล็อกเสียงบน iOS ไปพร้อมกัน) |
| ปฏิเสธสิทธิ์ | พูดบอกวิธีเปิดสิทธิ์ในตั้งค่าเบราว์เซอร์ + ปุ่ม "ลองใหม่" และหยุด watch เพื่อไม่เปลืองแบต |
| อยู่ในอาคาร / อับสัญญาณ | พูดแนะนำให้ย้ายไปที่โล่ง แต่ **ไม่หยุด watch** เผื่อสัญญาณกลับมาเอง |
| หาตำแหน่งแรกนานเกิน 15 วินาที | พูดว่า timeout + ปุ่มลองใหม่ |
| เปิดผ่าน HTTP (ไม่ใช่ HTTPS) | ตรวจ `isSecureContext` แล้วบอกสาเหตุตรงๆ แทนที่จะปล่อยให้ timeout งงๆ |
| สัญญาณหายกลางทาง | บางแพลตฟอร์ม `watchPosition` เงียบไปเฉยๆ ไม่ยิง error — จึงมีตัวจับเวลา 20 วินาที ถ้าไม่มีตำแหน่งใหม่จะเตือนว่า "ตำแหน่งที่แสดงอาจเป็นตำแหน่งเก่า" |
| ความแม่นยำแย่กว่า 50 เมตร | พูดเตือนพร้อมบอกค่าคลาดเคลื่อนจริง หมุดและวงรัศมีเปลี่ยนเป็นสีส้ม และพูดซ้ำได้ไม่เกินทุก 60 วินาที เพื่อไม่รบกวน |

เสียงพูดจัดคิวเอง (`webSpeechService`) ไม่ยิงซ้อนกัน และข้อความระดับ `critical` เช่นสัญญาณหาย จะตัดคิวที่ค้างอยู่เพื่อให้ได้ยินทันที

## การนำทางด้วยเสียง (Phase 2)

### ค้นหาจุดหมาย

รองรับพิมพ์ไทยและอังกฤษ ป้องกัน rate limit ของ Nominatim **สามชั้น**:

1. **debounce 1 วินาที** ที่ช่องค้นหา ([useSearch](src/hooks/useSearch.ts))
2. **cache ในหน่วยความจำ** อายุ 10 นาที — คำค้นซ้ำไม่ยิง API เลย (วัดได้: ครั้งแรก 351 ms → ครั้งที่สอง 0 ms)
3. **ตัวคุมคิว** บังคับให้ทุกคำขอที่ออกจากแอปห่างกันอย่างน้อย 1.1 วินาที ([requestQueue](src/services/impl/requestQueue.ts))

คำขอเดิมถูก abort ทุกครั้งที่ผู้ใช้พิมพ์ต่อ จึงไม่มีผลลัพธ์เก่ามาทับผลใหม่

### คำสั่งเสียง turn-by-turn

ระยะที่เตือนก่อนถึงจุดเลี้ยว: **100 → 50 → 20 → 8 เมตร** พูดเกณฑ์ละครั้งเท่านั้น (ล็อกไว้ด้วย Set ที่ล้างเมื่อเปลี่ยนขั้นตอน) ที่ 20 เมตรและใกล้กว่านั้นใช้ระดับ `critical` ซึ่งจะตัดคิวเสียงที่ค้างอยู่

- เข้าช่วงใหม่: "เดินตรงไปอีก 50 เมตร แล้วเลี้ยวซ้าย เข้าสู่ ถนนพระรามที่ 1"
- ใกล้ถึงจุดเลี้ยว: "อีก 20 เมตร เลี้ยวซ้าย"
- ถึงจุดเลี้ยว: "เลี้ยวซ้ายตอนนี้"

### ออกนอกเส้นทาง

ตรวจด้วยระยะจากตำแหน่งถึงเส้นทาง (point-to-polyline) เกิน 40 เมตร **ติดกัน 2 ครั้ง** และจะ**ข้ามการตรวจทั้งหมดถ้า GPS แม่นยำแย่กว่า 30 เมตร** มิฉะนั้นสัญญาณแกว่งในเมืองจะทำให้ยิงคำนวณเส้นทางใหม่รัวๆ ทั้งที่ผู้ใช้เดินถูกทาง

### การทดสอบตรรกะนำทาง

ตรรกะหลักถูกแยกเป็นฟังก์ชันบริสุทธิ์ที่ [utils/navigation.ts](src/utils/navigation.ts) จึงจำลองการเดินทั้งเส้นทางได้โดยไม่ต้องออกไปเดินจริง — จำลองด้วยเส้นทางจริงจาก OSRM 188 จุด (ทุก 4 เมตร) ทั้งแบบไม่มีและมีสัญญาณรบกวน ±10 เมตร

การจำลองนี้จับบั๊กจริงได้หนึ่งตัว: ระบบไม่เคยประกาศ "ถึงจุดหมาย" เพราะ OSRM snap ปลายทางเข้าถนนที่ใกล้ที่สุด ทำให้ปลายเส้นทางห่างจากพิกัดอาคารถึง **76 เมตร** ซึ่งเกินรัศมี 25 เมตรที่ใช้ตัดสิน
แก้โดยถือว่าถึงแล้วเมื่อ*เข้าใกล้พิกัดจุดหมาย* **หรือ** *เดินจนสุดปลายเส้นทาง* อย่างใดอย่างหนึ่ง และถ้ายังห่างจากตัวสถานที่ ระบบจะพูดบอกว่า "จุดหมายอยู่ห่างจากคุณประมาณ 76 เมตร เส้นทางเดินเท้าพาไปได้ถึงแค่จุดนี้"

**ข้อจำกัดที่ทราบ:** ถ้าจุดเลี้ยวสองจุดอยู่ห่างกันไม่ถึง ~10 เมตร และสัญญาณ GPS แกว่ง ระบบอาจข้ามการประกาศจุดเลี้ยวหนึ่งจุด (จะปรับปรุงโดยรวมคำสั่งเป็นประโยคเดียวใน Phase 4)

## ระบบ 2 ภาษา (Phase 3)

ครอบคลุมทั้ง UI และ **ข้อความเสียงทุกประโยค** — 117 คีย์เท่ากันทั้งสองภาษา

| ส่วน | รายละเอียด |
| --- | --- |
| ไฟล์แปล | [th.json](src/i18n/locales/th.json), [en.json](src/i18n/locales/en.json) |
| จำภาษาที่เลือก | `localStorage` คีย์ `taathip.language` — เปิดแอปครั้งถัดไปจำได้ |
| ภาษาเริ่มต้น | ภาษาที่เคยเลือก → ภาษาของเบราว์เซอร์ → ไทย |
| เสียงพูด | เลือก voice ให้ตรงภาษาอัตโนมัติ (`th-TH` / `en-US`) ผูกไว้ที่ [i18n/index.ts](src/i18n/index.ts) จุดเดียว |
| ผลค้นหา | ส่ง `accept-language` ตามภาษาที่เลือกไปให้ Nominatim ทั้งการค้นหาและ reverse geocoding |
| ปุ่มสลับภาษา | อยู่บนหัวแอป ขนาด ≥48px, `aria-label` เขียนด้วย**ภาษาปลายทาง** ("เปลี่ยนเป็นภาษาอังกฤษ") ผู้ใช้จึงรู้ว่ากดแล้วได้อะไร |

### รายละเอียดที่ทำเพื่อผู้ใช้ที่มองไม่เห็นโดยเฉพาะ

- **สลับภาษาแล้วยกเลิกเสียงที่ค้างในคิวทันที** ไม่งั้นจะได้ยินภาษาเก่าต่อจนจบแล้วค่อยเปลี่ยน
- **เตือนเมื่ออุปกรณ์ไม่มีเสียงของภาษาที่เลือก** — เครื่องที่ไม่มีเสียงภาษาไทยจะอ่านไทยด้วยเสียงอังกฤษซึ่งฟังแทบไม่รู้เรื่อง ผู้ใช้ที่มองไม่เห็นจะไม่มีทางรู้สาเหตุถ้าไม่บอก (`useVoiceAvailability` รอ 1.5 วินาทีให้รายชื่อเสียงโหลดก่อนสรุป)
- **แยกคีย์ตามโครงประโยค** เช่น `stepInstruction` กับ `stepInstructionWithStreet` เพราะไทยกับอังกฤษวางชื่อถนนคนละที่ ("แล้วเลี้ยวซ้าย เข้าสู่ ถนนพระรามที่ 1" vs "then turn left onto Rama I Road")
- **รูปพหูพจน์ของอังกฤษถูกต้อง** ผ่านระบบ plural ของ i18next ("1 minute" / "5 minutes") ขณะที่ไทยใช้รูปเดียว

### การตรวจสอบ

มีสคริปต์ตรวจว่า **ทุกคีย์ในทั้งสองภาษาแปลผลได้จริง** ไม่มีคีย์ขาด ไม่มีตัวแปร `{{...}}` ตกค้าง และไม่มีคำแปลว่าง รวมถึงตรวจว่า `ManeuverType` ทั้ง 12 ค่า และรหัสข้อผิดพลาดทั้ง 12 รหัส มีคำแปลครบทั้งแบบแสดงผลและแบบพูด

## ฟีเจอร์ความปลอดภัย (Phase 4)

### ปุ่ม SOS — กดค้าง 3 วินาที

**ทำไมต้องกดค้าง ไม่ใช่กดครั้งเดียว:** ผู้ใช้ที่มองไม่เห็นสำรวจหน้าจอด้วยการแตะ ปุ่มที่ทำงานทันทีจะถูกกดโดนโดยไม่ตั้งใจได้ง่ายมาก และการแจ้งเตือนฉุกเฉินผิดพลาดสร้างความตื่นตระหนกให้คนที่ห่วงใยผู้ใช้

ระหว่างกดค้างจะ**นับถอยหลังด้วยเสียงและการสั่นทุกวินาที (3, 2, 1)** ผู้ใช้จึงรู้ว่ากดติดแล้ว และรู้ว่าเหลือเวลาอีกเท่าไรถ้าจะยกนิ้วยกเลิก — ยกนิ้วก่อนครบเวลาจะได้ยิน "ยกเลิกแล้ว ไม่มีข้อความถูกส่งออกไป" รองรับคีย์บอร์ด/สวิตช์ด้วย (กดค้าง Enter หรือ Space)

เมื่อครบ 3 วินาที: เปิดแอปข้อความพร้อมข้อความและลิงก์แผนที่ที่เตรียมไว้ให้แล้ว ส่งไปยังผู้ติดต่อฉุกเฉินคนแรก (ถ้าไม่ได้ตั้งไว้ จะใช้แผงแชร์ของระบบ หรือคัดลอกลงคลิปบอร์ดเป็นทางสุดท้าย)

> **แอปไม่ส่งข้อความเอง** เพราะเบราว์เซอร์ทำไม่ได้และไม่ควรทำ — ผู้ใช้ต้องเห็นและกดส่งเองในแอปข้อความ ซึ่งเป็นการยืนยันอีกชั้นก่อนข้อมูลจะออกจากเครื่อง

### แชร์ตำแหน่ง — ข้อจำกัดที่ต้องเข้าใจตรงกัน

> ⚠️ **แอปนี้ไม่มีเซิร์ฟเวอร์ของตัวเอง ลิงก์ที่สร้างจึงเป็น "ภาพนิ่งของตำแหน่ง ณ เวลาที่กดส่ง" ไม่ใช่การติดตามแบบเรียลไทม์**
> การติดตามสดจริงต้องมีเซิร์ฟเวอร์คอยรับตำแหน่งเป็นระยะ ซึ่งแลกมาด้วยการที่ตำแหน่งของผู้ใช้ต้องออกจากเครื่องไปเก็บไว้ที่อื่น

สิ่งที่ทำได้จริงโดยไม่มีเซิร์ฟเวอร์ และทำไว้แล้ว:

- ข้อมูลตำแหน่งฝังอยู่ใน **fragment (`#`) ของ URL ซึ่งเบราว์เซอร์ไม่ส่งไปยังเซิร์ฟเวอร์** ตำแหน่งจึงไม่ปรากฏใน access log ของโฮสต์ใดๆ รวมถึง Vercel
- **ลิงก์มีวันหมดอายุฝังอยู่ในตัว** เปิดหลังหมดอายุจะไม่แสดงตำแหน่ง (ค่าเริ่มต้น 1 ชั่วโมง)
- **ถึงจุดหมายแล้วเซสชันปิดอัตโนมัติ** พร้อมแจ้งด้วยเสียง
- ปุ่ม "ส่งตำแหน่งล่าสุด" สำหรับอัปเดต และ**หน้าที่ผู้รับเห็นจะเตือนชัดเจน**ว่าเป็นภาพนิ่ง หมุดจะไม่ขยับเอง — เพราะถ้าคนดูเข้าใจผิดว่าเป็นเรียลไทม์แล้วเห็นหมุดนิ่ง อาจนิ่งนอนใจทั้งที่ผู้ใช้กำลังต้องการความช่วยเหลือ

ถ้าจะทำติดตามสดจริงในอนาคต: เขียน implementation ใหม่ของ `ShareService` ที่คุยกับเซิร์ฟเวอร์ แล้วสลับที่ [services/index.ts](src/services/index.ts) — ส่วนอื่นของแอปไม่ต้องแก้

### เตือนจุดเสี่ยง

ใช้ `intersections` จาก route steps ของ OSRM โดยเตือนล่วงหน้า **35 เมตร** (ไกลกว่าคำเตือนจุดเลี้ยวที่ 20 เมตร เพื่อให้ได้ยิน "ระวังสี่แยก" ก่อนคำสั่งเลี้ยว จะได้ชะลอฝีเท้าก่อนถึงจุดตัดสินใจ)

**เกณฑ์ผ่านการจูนด้วยข้อมูลจริงในกรุงเทพฯ:** เกณฑ์แรกที่ใช้คือ "แยกตั้งแต่ 3 แขน" ซึ่งกวาดไป 6 จาก 8 ขั้นตอน จนคำเตือนไร้ความหมาย จึงเปลี่ยนเป็น:

1. **สี่แยก** (4 แขนขึ้นไป) — รถมาได้หลายทิศพร้อมกัน
2. **ถนนใหญ่ที่มีชื่อ** (ขึ้นต้นด้วย "ถนน" หรือลงท้ายด้วย Road / Avenue / Highway)

ผลหลังจูน: 4/8 และ 11/25 ขั้นตอน (≈ 1 คำเตือนต่อ 270 เมตร) โดย**ตัดซอยเล็กที่เป็นแค่ทางแยกสามแขนออกได้ถูกต้อง**

> ⚠️ ข้อมูลฟรีของ OSRM **ไม่ได้ระบุว่ามีทางม้าลายหรือสัญญาณไฟจริงหรือไม่** คำเตือนนี้จึงเป็นการให้ "ระวังไว้ก่อน" ไม่ใช่การยืนยันว่ามีทางข้าม — ข้อความนี้แสดงในแอปให้ผู้ใช้เห็นด้วย

### สั่นเตือน (Vibration API)

| เหตุการณ์ | รูปแบบ |
| --- | --- |
| แตะปุ่มติด | สั้น 1 จังหวะ |
| ใกล้จุดเลี้ยว (20 ม.) | ยาว 1 จังหวะ |
| จุดเสี่ยงข้างหน้า | 2 จังหวะ |
| ส่ง SOS แล้ว | 3 จังหวะยาว |

จำนวนจังหวะสื่อความหมายได้โดยไม่ต้องฟังเสียง เผื่ออยู่ในที่เสียงดัง — และเป็น**ช่องทางเสริมเสมอ ไม่ใช่ช่องทางเดียว** เพราะ iOS Safari ยังไม่รองรับ Vibration API (แอปจะแสดงข้อความบอกและปิดตัวเลือกให้เอง)

## ความเป็นส่วนตัว (PDPA)

### แอปเก็บอะไรบ้าง

| ข้อมูล | เก็บที่ไหน | อยู่นานแค่ไหน |
| --- | --- | --- |
| ภาษาที่เลือก | `localStorage` (`taathip.language`) | จนกว่าผู้ใช้จะลบ |
| ผู้ติดต่อฉุกเฉิน (ชื่อ + เบอร์) | `localStorage` (`taathip.settings`) | จนกว่าผู้ใช้จะลบ |
| ตัวเลือกการสั่น/การเตือน | `localStorage` (`taathip.settings`) | จนกว่าผู้ใช้จะลบ |
| ผลค้นหาสถานที่ (cache) | หน่วยความจำเท่านั้น | 10 นาที หรือปิดแอป |

### แอป **ไม่** เก็บอะไร

- ❌ **ไม่เก็บประวัติตำแหน่ง** — ตำแหน่งอยู่ใน state ของแอประหว่างใช้งานเท่านั้น ปิดแอปแล้วหายทันที ไม่มีการเขียนลงดิสก์
- ❌ **ไม่เก็บประวัติเส้นทางที่เคยไป**
- ❌ **ไม่มีบัญชีผู้ใช้ ไม่มีการติดตามพฤติกรรม ไม่มี analytics ไม่มี cookie**
- ❌ **ไม่มีเซิร์ฟเวอร์ของแอปเอง** — ไม่มีข้อมูลใดถูกส่งมาเก็บฝั่งเรา เพราะไม่มีฝั่งเรา

### ข้อมูลออกจากเครื่องเมื่อไร

มีเพียง 3 กรณี และทั้งหมดเกิดจากการกระทำของผู้ใช้:

1. **ค้นหาสถานที่** — คำค้นถูกส่งไปยัง Nominatim (OpenStreetMap Foundation)
2. **คำนวณเส้นทาง / ถามว่าอยู่ที่ไหน** — พิกัดถูกส่งไปยัง OSRM ของ FOSSGIS และ Nominatim
3. **กด SOS หรือแชร์ตำแหน่ง** — ผู้ใช้เป็นคนกดส่งเองในแอปข้อความ/แผงแชร์ของระบบ

โหลด tile แผนที่จาก OpenStreetMap ก็ทำให้ผู้ให้บริการทราบพื้นที่คร่าวๆ ที่กำลังดูอยู่ ตามปกติของการใช้แผนที่ออนไลน์ทุกเจ้า

ผู้ใช้ลบข้อมูลได้เองด้วยปุ่ม **"ลบผู้ติดต่อและการตั้งค่าที่บันทึกไว้"** ในหน้าตั้งค่าความปลอดภัย (ต้องแตะสองครั้งเพื่อยืนยัน ด้วยเหตุผลเดียวกับที่ปุ่ม SOS ต้องกดค้าง — กันการกดโดนโดยไม่ตั้งใจจนเบอร์ฉุกเฉินหายไปโดยไม่รู้ตัว) ภาษาที่เลือกไว้จะยังคงอยู่ เพราะเป็นการตั้งค่าหน้าตาแอป ไม่ใช่ข้อมูลส่วนบุคคล

## PWA และการใช้งานออฟไลน์ (Phase 5)

ติดตั้งลงหน้าจอโฮมได้ทั้ง Android และ iOS (manifest + service worker ผ่าน `vite-plugin-pwa`)

### แคชอะไรบ้าง

| ทรัพยากร | กลยุทธ์ | เหตุผล |
| --- | --- | --- |
| หน้าตาแอป (HTML/JS/CSS/ไอคอน) | precache | เปิดแอปได้แม้ไม่มีเน็ต |
| tile แผนที่ที่เคยโหลด | `CacheFirst` เก็บ 500 ชิ้น 14 วัน | ดูแผนที่บริเวณที่เคยไปได้ตอนออฟไลน์ โดยไม่กินพื้นที่เครื่องเกินควรและเคารพนโยบายของ OSM |
| Nominatim / OSRM | **`NetworkOnly` ไม่แคชเด็ดขาด** | ถ้าเผลอแคชไว้ ผู้ใช้อาจได้เส้นทางเก่าที่ไม่ตรงกับตำแหน่งจริงโดยไม่รู้ตัว ซึ่งอันตราย |

### ตอนออฟไลน์เกิดอะไรขึ้น

- **แถบเตือนบนหน้าจอ + พูดออกเสียงทันที** ว่า "แผนที่ที่โหลดไว้แล้วยังดูได้ แต่ค้นหาสถานที่และคำนวณเส้นทางใหม่ใช้ไม่ได้"
  (สำคัญมาก เพราะแผนที่ที่แคชไว้ยังแสดงอยู่ ผู้ใช้ที่มองไม่เห็นจึงไม่มีทางรู้เองว่าระบบใช้งานได้ไม่ครบแล้ว)
- ช่องค้นหาถูกปิดพร้อมบอกเหตุผล
- เมื่อกลับมาออนไลน์จะพูดบอกว่าใช้งานได้ครบแล้ว

### อัปเดตเวอร์ชันใหม่

ใช้โหมด `prompt` **ไม่อัปเดตอัตโนมัติ** เพราะการรีโหลดกลางทางจะทำให้การนำทางที่กำลังทำอยู่หลุด ซึ่งอันตรายกับคนที่กำลังเดินอยู่ — แอปจะขึ้นแถบถามและให้ผู้ใช้เลือกจังหวะเอง

### ไอคอน

สร้างจากโค้ดด้วย `npm run icons` ([scripts/generate-icons.mjs](scripts/generate-icons.mjs)) ซึ่งเขียน PNG encoder เองด้วย `node:zlib` จึงไม่ต้องติดตั้ง ImageMagick / sharp ให้ครบทุกเครื่อง ได้ครบทั้ง 64/180/192/512 และรุ่น maskable ที่เผื่อพื้นที่ปลอดภัย 80% ตรงกลาง

## Deploy ขึ้น Vercel

1. push โค้ดขึ้น GitHub
2. เข้า [vercel.com](https://vercel.com) → **Add New → Project** → เลือก repo นี้
3. Vercel ตรวจเป็น **Vite** ให้อัตโนมัติ ค่าที่ควรเห็น:
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Install Command: `npm install`
4. **ไม่ต้องตั้ง Environment Variable ใดๆ** — OSM / Nominatim / OSRM ใช้ฟรีไม่ต้องใช้ key
5. กด Deploy

ไม่ต้องมี `vercel.json` เพราะแอปใช้ hash routing (`#/share/...`) จึงไม่ต้องตั้ง rewrite ให้ SPA

### ทำไมต้อง deploy ถึงจะทดสอบได้จริง

Geolocation API และ Web Speech API ทำงานเฉพาะบน **HTTPS หรือ localhost** เท่านั้น เปิดผ่าน `http://192.168.x.x:5173` บนมือถือจะขอตำแหน่งไม่ได้ — ใช้ URL ของ Vercel หรือ tunnel เช่น `ngrok http 5173`

### ตรวจหลัง deploy

- เปิดจากมือถือ → ควรมีตัวเลือก "เพิ่มลงหน้าจอโฮม" (Android: แถบ install / iOS: แชร์ → เพิ่มไปยังหน้าจอโฮม)
- เปิดโหมดเครื่องบินหลังใช้ครั้งแรก → แอปยังเปิดได้ แผนที่บริเวณเดิมยังเห็น และมีแถบเตือนออฟไลน์
- ทดสอบด้วย Lighthouse หมวด PWA และ Accessibility
