# ตาทิพย์ Navigator (Taa-Thip Navigator)

แอปนำทางด้วยเสียงสำหรับผู้พิการทางสายตา — Progressive Web App ต่อยอดจากโปรเจกต์ **ตาทิพย์** (เครื่องอ่านฉลากยาด้วย AI)

> **สถานะปัจจุบัน: Phase 2 เสร็จแล้ว** — ค้นหาจุดหมาย + เส้นทางเดินเท้า + นำทาง turn-by-turn ด้วยเสียง

## Tech Stack

| ส่วน | เทคโนโลยี | ต้องใช้ API key |
| --- | --- | --- |
| Framework | React 19 + Vite + TypeScript | – |
| Styling | Tailwind CSS v4 | – |
| แผนที่ | Leaflet + react-leaflet + OpenStreetMap tiles | ไม่ต้อง |

| เสียง | Web Speech API (SpeechSynthesis / SpeechRecognition) | – |
| 2 ภาษา | react-i18next (th / en) | – |

### ทดสอบบนมือถือจริง

Geolocation API และ Web Speech API **ต้องรันบน HTTPS หรือ localhost เท่านั้น** เปิดผ่าน `http://192.168.x.x:5173`
เบราว์เซอร์จะไม่ยอมให้ขอตำแหน่ง ทางเลือก:

- deploy ขึ้น Vercel แล้วเปิดจากมือถือ (ง่ายที่สุด)
- หรือใช้ tunnel เช่น `ngrok http 5173`

## โครงสร้างโปรเจกต์

```
src/
├── components/          # UI components
├── hooks/               # React hooks (useGeolocation, useSpeech, ...)
├── services/
│   ├── interfaces/      # ⭐ interface กลาง — ไม่ผูกกับผู้ให้บริการรายใดรายหนึ่ง
│   │   ├── mapService.ts
│   │   ├── geocodingService.ts
│   │   ├── routingService.ts
│   │   └── speechService.ts
│   ├── impl/            # implementation จริง (OSM / Nominatim / OSRM)
│   ├── config.ts        # URL + ค่าคงที่ของผู้ให้บริการ
│   └── index.ts         # composition root — จุดเดียวที่ผูก interface กับ impl
├── i18n/
│   ├── messages.ts      # ข้อความไทยชั่วคราว (Phase 3 จะย้ายไป react-i18next)
│   └── locales/         # th.json, en.json
├── types/               # โดเมนไทป์กลาง (LatLng, Route, RouteStep, ...)
├── context/
└── utils/
```

### หลักการ service layer (สำคัญ)

ทุก component และ hook **ต้อง import จาก `@/services` เท่านั้น ห้าม import จาก `services/impl/` โดยตรง**
ถ้าวันหนึ่งอยากย้ายจาก OpenStreetMap ไป Google Maps:

1. เขียน implementation ใหม่ใน `services/impl/` ที่ implement interface เดิม
2. แก้บรรทัดผูก implementation ใน `services/index.ts` บรรทัดเดียว
3. ไม่ต้องแตะ component / hook ใดๆ

โดเมนไทป์กลาง (`LatLng`, `Route`, `RouteStep`, `ManeuverType`) ถูกออกแบบให้เป็นกลาง ไม่ใช่ shape ของ OSRM หรือ Leaflet
ดังนั้น implementation มีหน้าที่แปลงข้อมูลของผู้ให้บริการมาเป็นไทป์กลางเสมอ

## ⚠️ ข้อจำกัดของบริการฟรี (อ่านก่อนใช้งานจริง)

โปรเจกต์นี้ใช้บริการสาธารณะฟรีทั้งหมด **เหมาะกับงานเรียน / ต้นแบบ / เดโม เท่านั้น** ไม่เหมาะกับโปรดักชันจริงที่มีผู้ใช้จำนวนมาก

### Nominatim (ค้นหาสถานที่)

- นโยบายกำหนด **ไม่เกิน 1 คำขอต่อวินาที** ยิงถี่กว่านี้อาจโดนบล็อก IP
- ห้ามใช้ทำ bulk geocoding
- โปรเจกต์นี้ป้องกันด้วย: debounce การค้นหา 1 วินาที (`SEARCH_DEBOUNCE_MS`), ตัวคุมคิวคำขอขั้นต่ำ 1.1 วินาที (`NOMINATIM_MIN_INTERVAL_MS`), และ cache ผลลัพธ์ที่ค้นซ้ำ (Phase 4)

### OSRM (คำนวณเส้นทาง) — มีข้อควรระวังสำคัญ

> ⚠️ **`router.project-osrm.org` (demo server) ติดตั้งไว้เฉพาะ profile รถยนต์**
> ตรวจสอบแล้วด้วยพิกัดชุดเดียวกัน: เรียก `/driving/`, `/foot/`, `/walking/`, `/bike/` ได้ผลลัพธ์ **เท่ากันเป๊ะทุก profile** (1,621 ม. / 197 วิ = ~29 กม./ชม. ซึ่งเป็นความเร็วรถ)
> สำหรับแอปนำทางคนตาบอด นี่คือปัญหาด้านความปลอดภัย เพราะจะพาเดินตามถนนรถ ไม่ใช้ทางเท้า ไม่สนใจทางข้าม และบอกเวลาผิดหลายเท่า

โปรเจกต์นี้จึงใช้ **`routing.openstreetmap.de/routed-foot`** ของ FOSSGIS (อินสแตนซ์เดียวกับที่เว็บ openstreetmap.org ใช้) ซึ่งติดตั้ง profile เดินเท้าไว้จริง — เส้นทางเดียวกันได้ 742 ม. / 593 วิ (1.25 ม./วิ) และใช้ทางเดินในซอย

- ยังคงเป็นบริการฟรีแบบ fair use **ไม่มี SLA** ห้ามใช้งานหนัก
- ถ้า FOSSGIS ล่ม ระบบจะถอยไปใช้ demo server อัตโนมัติ แต่จะ **ติดธง `usedFallbackProfile`** และ **พูดเตือนผู้ใช้** ว่าเป็นเส้นทางรถ พร้อมคำนวณเวลาใหม่ด้วยความเร็วเดิน (1.25 ม./วิ) แทนเวลาขับรถ
- โปรเจกต์นี้ป้องกันเพิ่มด้วย: จำกัดการคำนวณเส้นทางใหม่ไม่ถี่กว่า 30 วินาที/ครั้ง + retry แบบ exponential backoff + แจ้งเตือนด้วยเสียงทันทีเมื่อบริการล่ม

### OpenStreetMap tile server

- มี [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) ห้าม bulk download tile และต้องแสดง attribution เสมอ

### ถ้าจะขยายเป็นโปรดักชันจริง

| ต้องการ | ทางเลือก |
| --- | --- |
| Geocoding | self-host Nominatim, หรือใช้ Photon / LocationIQ / Mapbox / Google Places (มีค่าใช้จ่าย) |
| Routing | self-host OSRM หรือ Valhalla, หรือ GraphHopper / Mapbox Directions |
| Tiles | MapTiler / Stadia Maps / Mapbox หรือ self-host tile server |

โครงสร้าง service layer ของโปรเจกต์นี้ออกแบบมาเพื่อรองรับการย้ายเหล่านี้อยู่แล้ว

## การจัดการ GPS (Phase 1)

`useGeolocation` ใช้ `watchPosition` และครอบเคสที่ผู้ใช้ตาบอดจะเดือดร้อนถ้าไม่จัดการ — **ทุกเคสมีเสียงพูดบอก ไม่ใช่แค่ข้อความบนจอ**

| สถานการณ์ | สิ่งที่เกิดขึ้น |
| --- | --- |
| ยังไม่กดเริ่ม | ไม่ขอสิทธิ์อัตโนมัติ — อธิบายเหตุผลก่อน แล้วให้ผู้ใช้แตะปุ่มเอง (โปร่งใส + ปลดล็อกเสียงบน iOS ไปพร้อมกัน) |
| ปฏิเสธสิทธิ์ | พูดบอกวิธีเปิดสิทธิ์ในตั้งค่าเบราว์เซอร์ + ปุ่ม "ลองใหม่" และหยุด watch เพื่อไม่เปลืองแบต |
| อยู่ในอาคาร / อับสัญญาณ | พูดแนะนำให้ย้ายไปที่โล่ง แต่ **ไม่หยุด watch** เผื่อสัญญาณกลับมาเอง |
| หาตำแหน่งแรกนานเกิน 15 วินาที | พูดว่า timeout + ปุ่มลองใหม่ |
| เปิดผ่าน HTTP (ไม่ใช่ HTTPS) | ตรวจ `isSecureContext` แล้วบอกสาเหตุตรงๆ แทนที่จะปล่อยให้ timeout งงๆ |
| สัญญาณหายกลางทาง | บางแพลตฟอร์ม `watchPosition` เงียบไปเฉยๆ ไม่ยิง error — จึงมีตัวจับเวลา 20 วินาที ถ้าไม่มีตำแหน่งใหม่จะเตือนว่า "ตำแหน่งที่แสดงอาจเป็นตำแหน่งเก่า" |
| ความแม่นยำแย่กว่า 50 เมตร | พูดเตือนพร้อมบอกค่าคลาดเคลื่อนจริง หมุดและวงรัศมีเปลี่ยนเป็นสีส้ม และพูดซ้ำได้ไม่เกินทุก 60 วินาที เพื่อไม่รบกวน |

เสียงพูดจัดคิวเอง (`webSpeechService`) ไม่ยิงซ้อนกัน และข้อความระดับ `critical` เช่นสัญญาณหาย จะตัดคิวที่ค้างอยู่เพื่อให้ได้ยินทันที

## การนำทางด้วยเสียง (Phase 2)

### ค้นหาจุดหมาย

รองรับพิมพ์ไทยและอังกฤษ ป้องกัน rate limit ของ Nominatim **สามชั้น**:

1. **debounce 1 วินาที** ที่ช่องค้นหา ([useSearch](src/hooks/useSearch.ts))
2. **cache ในหน่วยความจำ** อายุ 10 นาที — คำค้นซ้ำไม่ยิง API เลย (วัดได้: ครั้งแรก 351 ms → ครั้งที่สอง 0 ms)
3. **ตัวคุมคิว** บังคับให้ทุกคำขอที่ออกจากแอปห่างกันอย่างน้อย 1.1 วินาที ([requestQueue](src/services/impl/requestQueue.ts))

คำขอเดิมถูก abort ทุกครั้งที่ผู้ใช้พิมพ์ต่อ จึงไม่มีผลลัพธ์เก่ามาทับผลใหม่

### คำสั่งเสียง turn-by-turn

ระยะที่เตือนก่อนถึงจุดเลี้ยว: **100 → 50 → 20 → 8 เมตร** พูดเกณฑ์ละครั้งเท่านั้น (ล็อกไว้ด้วย Set ที่ล้างเมื่อเปลี่ยนขั้นตอน) ที่ 20 เมตรและใกล้กว่านั้นใช้ระดับ `critical` ซึ่งจะตัดคิวเสียงที่ค้างอยู่

- เข้าช่วงใหม่: "เดินตรงไปอีก 50 เมตร แล้วเลี้ยวซ้าย เข้าสู่ ถนนพระรามที่ 1"
- ใกล้ถึงจุดเลี้ยว: "อีก 20 เมตร เลี้ยวซ้าย"
- ถึงจุดเลี้ยว: "เลี้ยวซ้ายตอนนี้"

### ออกนอกเส้นทาง

ตรวจด้วยระยะจากตำแหน่งถึงเส้นทาง (point-to-polyline) เกิน 40 เมตร **ติดกัน 2 ครั้ง** และจะ**ข้ามการตรวจทั้งหมดถ้า GPS แม่นยำแย่กว่า 30 เมตร** มิฉะนั้นสัญญาณแกว่งในเมืองจะทำให้ยิงคำนวณเส้นทางใหม่รัวๆ ทั้งที่ผู้ใช้เดินถูกทาง

### การทดสอบตรรกะนำทาง

ตรรกะหลักถูกแยกเป็นฟังก์ชันบริสุทธิ์ที่ [utils/navigation.ts](src/utils/navigation.ts) จึงจำลองการเดินทั้งเส้นทางได้โดยไม่ต้องออกไปเดินจริง — จำลองด้วยเส้นทางจริงจาก OSRM 188 จุด (ทุก 4 เมตร) ทั้งแบบไม่มีและมีสัญญาณรบกวน ±10 เมตร

การจำลองนี้จับบั๊กจริงได้หนึ่งตัว: ระบบไม่เคยประกาศ "ถึงจุดหมาย" เพราะ OSRM snap ปลายทางเข้าถนนที่ใกล้ที่สุด ทำให้ปลายเส้นทางห่างจากพิกัดอาคารถึง **76 เมตร** ซึ่งเกินรัศมี 25 เมตรที่ใช้ตัดสิน
แก้โดยถือว่าถึงแล้วเมื่อ*เข้าใกล้พิกัดจุดหมาย* **หรือ** *เดินจนสุดปลายเส้นทาง* อย่างใดอย่างหนึ่ง และถ้ายังห่างจากตัวสถานที่ ระบบจะพูดบอกว่า "จุดหมายอยู่ห่างจากคุณประมาณ 76 เมตร เส้นทางเดินเท้าพาไปได้ถึงแค่จุดนี้"

**ข้อจำกัดที่ทราบ:** ถ้าจุดเลี้ยวสองจุดอยู่ห่างกันไม่ถึง ~10 เมตร และสัญญาณ GPS แกว่ง ระบบอาจข้ามการประกาศจุดเลี้ยวหนึ่งจุด (จะปรับปรุงโดยรวมคำสั่งเป็นประโยคเดียวใน Phase 4)
